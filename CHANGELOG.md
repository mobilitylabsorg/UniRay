# Изменения

Раздел версии попадает в описание её релиза на GitHub (`.github/workflows/build.yml`, задача Release).

## 0.3.0 — 2026-11-09

Изменения по сравнению с [0.2.0](https://github.com/mobilitylabsorg/UniRay/releases/tag/v0.2.0).

### Безопасность

- **Xray v26.11.9** вместо v26.9.30, с двумя срочными исправлениями upstream: MPTCP выключен по умолчанию (через MPTCP-сокет, слушающий по IPv4, уязвимость ядра Linux давала удалённый root; это касалось SOCKS/HTTP-порта шлюза в локальной сети и Android с подключениями из LAN), и сертификаты утёкших индийских промежуточных CA отсекаются — Xray собирается на Go 1.27.3. Ядро хоста шлюза (Proxmox, Docker) стоит обновить и самому: уязвимость в нём.

### Скорость

- **Новый TUN-стек Xray с нашей обработкой потерь.** С v26.11.9 TUN в Xray работает не на gVisor, а на своём небольшом стеке: в 6–10 раз меньше процессора на гигабайт — заметно на MikroTik. Потери на участке LAN он переносил как Reno, поэтому форк [mobilitylabsorg/Xray-core](https://github.com/mobilitylabsorg/Xray-core/tree/uniray-v26.11.9) добавляет порог перестановки вместо первого SACK, пол окна по скорости доставки (как в BBR) и быстрый повтор потерянного ретрансмита; при перегрузке всё это выключается. При 2% потерь: 94 / 629 МБ/с на 1 / 8 потоков против 7 / 54 у стокового v26.11.9; Wi-Fi с джиттером и 1% потерь — 45 / 239 против 3 / 20. Замеры и стенд (`bench/tun`) — в [README](https://github.com/mobilitylabsorg/UniRay/blob/main/README.md#tun-bbr).

### Изменено

- **Тест скорости**: вместо круглой шкалы — карточки загрузки, отдачи и пинга, которые обновляются прямо во время замера, и строка с текущим этапом.
- **«Что работает сейчас»**: добавлены WhatsApp, Notion и Canva, у каждого сервиса подпись; Steam, Twitch и Spotify убраны. Блокировка распознаётся и по странице-заглушке (Cloudflare, «Доступ ограничен»), а не только по коду ответа; ошибки подписаны понятнее: «Таймаут», «Сброс DPI», «Недоступен».

### Исправления

- WhatsApp в проверке сервисов больше не показывался недоступным при рабочем соединении.
- Сборка: NaiveProxy v154.0.8037.49-5 — файлы -4 удалены из его релиза.

### Обновления

- NaiveProxy v154.0.8037.49-5, Tauri 2.12.5 и плагины, Vue, Vite, Tailwind и прочие зависимости интерфейса — последние патч-версии.

## 0.2.0 — 2026-10-16

Изменения по сравнению с [0.1.0](https://github.com/mobilitylabsorg/UniRay/releases/tag/v0.1.0).

### Скорость

- **TUN на Xray с BBRv3 и RACK.** Xray во всех клиентах и в шлюзе собирается из форков [mobilitylabsorg/Xray-core](https://github.com/mobilitylabsorg/Xray-core/tree/uniray) и [mobilitylabsorg/libXray](https://github.com/mobilitylabsorg/libXray/tree/uniray) на нашем gVisor: вместо Cubic — BBRv3, включено обнаружение потерь RACK. Стоковый Xray на пути с 2% потерь (шлюз → роутер → устройство) падал до 0,5–1,6 МБ/с, форк держит 57–71 МБ/с; 16 параллельных загрузок — 816 МБ/с против 22, без зависаний. На живой сети TUN шлюза за роутером вырос с 0,5 до ~5 МБ/с. Подробнее — в [README](https://github.com/mobilitylabsorg/UniRay/blob/main/README.md#tun-bbr).

### Новое

- **Две сборки Android.** С GitHub — полная, как раньше (`dev.uniray.app`). Для Google Play — `dev.uniray.app.play`, ставится рядом: без stealth-режима и блокировки рекламы, которые правила Play не допускают; их кода в этой сборке нет вовсе, что CI проверяет на каждом бандле. Подробнее — в [README](https://github.com/mobilitylabsorg/UniRay/blob/main/README.md#android-editions).
- **Тест скорости**: 4 параллельных потока, загрузка, отдача, пинг и джиттер, сравнение «через VPN» и «напрямую», выбор тестового сервера, история замеров; круглая шкала-спидометр.
- **«Что работает сейчас»**: проверка YouTube, Telegram, Discord, ChatGPT и других сервисов.
- **«Почему не работает?»**: проверка сети оператора на блокировки и рекомендации по обходу DPI в одно нажатие.
- **Обход блокировок (DPI / ТСПУ)**: фрагментация TLS ClientHello, подмена uTLS-отпечатка (Chrome, Firefox, Safari, iOS, Edge, случайный), User-Agent подписки (Happ, Incy, v2rayNG и др.), MTU для WireGuard.
- **Блокировка рекламы и трекеров** (geosite).
- **Проверка задержки**: честный HTTP 204 через туннель или быстрый TCP до порта сервера, свой адрес проверки.
- **Серверы**: поиск, сортировка по пингу и имени, «Выбрать лучший», «Обновить всё», автообновление подписок раз в 6, 12 или 24 часа.
- **Резервная копия**: экспорт и импорт настроек, серверов и подписок (JSON).
- **Ссылки `uniray://`** на всех платформах: `connect`, `disconnect`, `toggle` и `import-sub?url=…` (подписка открывается в диалоге импорта, а не добавляется молча); ярлыки на рабочем столе Android.
- **Android TV**: управление пультом, крупный интерфейс с вкладками слева, импорт с телефона по QR-коду; APK для armv7 (ТВ-приставки) рядом с arm64.
- **Android**: «Не засыпать при выключенном экране»; экономия батареи — интерфейс засыпает в фоне, при выключенном экране служба реже будит систему; keep-alive TCP против обрывов соединений за CGNAT, MTU 1360 в мобильных сетях, простаивающие соединения закрываются через 60 с.
- **Шлюз**: шаблон LXC для Proxmox VE (amd64, arm64) и образ amd64; без `/etc/resolv.conf` DNS-сервером становится шлюз сети; в README — установка в Proxmox и настройка MikroTik для шлюза в той же подсети.

### Исправления

- Десктоп: тест скорости и проверка сервисов в режиме системного прокси шли мимо VPN, а замер «напрямую» в режиме TUN — через VPN; диагностика сети всегда видела «Wi-Fi». Теперь замер через VPN идёт через ядро, а напрямую — через физический интерфейс, тип сети и её DNS определяются по-настоящему.
- Android: ссылка `uniray://` с кавычкой могла выполнить скрипт в интерфейсе приложения.
- Android: список приложений для раздельного туннеля больше не требует разрешения на просмотр всех установленных приложений (`QUERY_ALL_PACKAGES`): видны те же приложения с иконкой в лаунчере.
- Сборка шлюза ломалась в системе с не-английской локалью (`readelf`).

### Сборка

- CI на раннерах GitHub: Linux, Windows, Android, шлюз и macOS (Apple Silicon и Intel) — в каждой сборке; для Google Play — отдельный бандл (AAB) в артефактах.
- TUN на macOS проверен вживую.
